# 初版实现和下一阶段边界

日期：2026-10-03。该记录对应当前可运行代码，优先于旧设计中“尚未实现”的状态描述；旧设计作为决策来源保留。

## 已实现

六角色业务合同和提示词编译；React/FastAPI 本机工作台；SQLite 版本历史、幂等与依赖失效；G0–G3 人工放行；真实证据来源分类；参考观察与迁移条件；实验记录；角色/场景/风格 Bible；素材导入及许可证据编辑；手动成果、人工验收和最终视频附件；官方 DeepSeek Harness 会话与 JSON 结果接入；费用预留及手工核账；不自动重放中断调用；FFmpeg 实际动态分镜 MP4、SRT、Manifest。

Agent只负责建议和专业文本成果。流程代码负责执行授权、门禁、版本与工具调用。角色互相不能自行批准或扩大权限。发送消息或确认交接时，会把Brief、交接包、专业资料及元数据发送给用户配置的模型服务；页面加载不调用模型。

## 有意先简化

- 初版使用两项并发的执行队列；六种职责分别配置，不部署六个常驻进程。后端重启保留未知外部调用为中断状态，用户核对后人工恢复。
- 各角色输入采用 JSON 快照。SDK 没有直接数据库写入或浏览工具；知识检索目前是人类录入参考加版本引用。
- 阶段决定由人类记录。主观审美与真实观众反馈不能用机械状态替代；G2 尚未自动检验工具实测材料真假。
- 费用以元为项目记账单位，由用户按供应商账单换算。预留金额不是模型供应商收费硬限额。
- 导出是动态分镜规划小样，默认保留视频首条原声，无声素材补静音；可叠加一条已导入音频作为旁白，控制音量和开始时间。字幕单独交付，音乐检索、多轨编辑和自动时间线尚未实现；旁白须由用户选择。
- 所有输入与成果有记录历史；UI 展示最新版，详细历史通过 API 读取。当前尚无复杂时间线编辑器、画面自动评分或跨项目资产复用。

## 关键风险与后续验证

1. 用户已配置DeepSeek并实际运行导演及四轮讨论；首轮截断已保留恢复记录，后续成功但仍有仅凭文字声称流程已落实的问题。本轮自动交接使用模拟运行器测试，真实接棒质量、延迟和账单仍待用户实际执行核对。
2. G0/G1/G2 记录的是接受何种风险后继续，不会自动证明假设。首个正式项目需选定真实受众和参考，约定测试条件，保留原始反馈。
3. 已实现 Seedream、万相、CosyVoice 和受限 Seedance 中转站适配器，持久 job ID、状态查询、超时取回与核账。账号权限、真实素材质量和收费仍需用户单镜试验；尚未实现供应商取消接口，不把 HTTP 超时当成未收费。
4. 本地设置保存凭证但未用系统密钥库。多用户或联网部署前需单独设计认证、加密、访问隔离和素材存储，不能直接改监听地址上线。
5. 仅已记录的依赖能自动失效。人工无引用的语义关系需要导演补齐，复杂跨项目关系未实现。
6. 成片五项评审仍由具备观看/收听条件的人类完成。自动检查可用于补充，不应伪装目标行为已经得到验证。

# 持续对话交互补充（2026-10-03）

用户反馈原成果展示难读，无法继续沟通。角色主入口改为对话：`chat_messages`保存用户与可见回答，`chat_jobs`保存每轮状态、会话和费用；旧任务成果只读带入首轮历史，第一次发送后固定存档。每轮用新Harness会话执行，并显式传入完整的本角色讨论历史、当前Brief、版本化参考、已验收上游成果及真实工作流状态。角色无需靠自由对话改变业务状态。

新回答先作为讨论草稿，任务进入`discussing`。人类可继续讨论；主路径通过“无异议，确认并交接”将最新完整回复定稿、验收、记录相应阶段决定并选取可执行下游，在同一事务保存调用意图，提交后只调度一次接棒回复。定稿不产生模型调用；接棒产生一轮预留。旧的单独整理、定稿、验收入口保留为高级操作。已验收任务不可直接继续修改，沿既有局部返工路径。正在回复时阻止同时发送、旧成果验收和定稿；输入变化后保留可见草稿但禁止批准。未知费用保留，重启不中继重放。对话GET在同一SQLite读快照中读取消息、调用和任务，避免回复结束时状态混杂。

前端以角色切换、消息历史和输入框为主，旧任务卡折叠。`react-markdown` + `remark-gfm`显示Markdown和表格，跳过原始HTML，不使用`dangerouslySetInnerHTML`；表格提供横向滚动。新轮次的交互提示约束短回答、处理分歧、少量问题和不重复全报告。真实模型是否始终遵守新风格仍待用户运行验证。

## 观众视频校验停用（2026-10-03）

`studio/capabilities.py`统一声明 `audience_mode=strategy_only` 与 `audience_video_validation.enabled=false`，通过只读API和项目快照公开。所有新任务运行及对话均收到能力上下文与系统补充约束：媒体元数据不能当作观看证据，不能声称已验证观众反应。观众对话显示停用提示，保留文字策划、阶段验收及真实人工反馈记录；G0验收策略方向，不自动证明假设。历史文字结果不重写，原六字段提示词版本不变，现有任务可继续。该策略不存在运行时启用开关；重新启用必须先接入并验证真实视频理解API。模型输出仍需人工审核，系统提示不能保证模型绝无虚构。

## Gemini 预置适配器（保持禁用）

用户选择 Gemini 后，新增 `GeminiSettings` 和 `GeminiVideoAdapter`，不改变六角色 DeepSeek 模型。`GET/PUT /api/gemini` 负责本机独立配置；只回传参数、has_key和disabled状态，不回传Key，配置校验错误也不回显请求输入。Key保存在 `data/gemini-settings.json`，与既有Key相同，尚未使用系统密钥库。

适配器依据官方 [Interactions API](https://ai.google.dev/api/interactions-api) 与 [视频理解文档](https://ai.google.dev/gemini-api/docs/video-understanding) 封装固定官方HTTPS地址，鉴权使用header，不在URL放Key。初版支持12MB以内的内联视频，static抽帧，低思考强度、输出上限、请求超时、无工具、store=false；响应只提取model_output可见文字和白名单token用量，隐藏思考及原始供应商错误。一次请求失败或超时不会自动重试。大文件Files API尚未实现。

应用只能使用公开analyze入口；它在读取Key/编码视频/请求网络前检查disabled能力。`POST /api/projects/{pid}/video-analysis`也直接拒绝，在禁用期间不读取素材、不创建任务、不预留费用。没有启用开关，配置enabled字段会被拒绝；保存Key不验证联网。底层传输仅在协议测试中使用MockTransport演练。未来启用前还需用户授权、真实API与素材实测、持久调用意图和请求ID、核账/恢复机制、素材版本追踪；不能只修改一个布尔值即上线。

## 确认后自动交接（2026-10-03）

`POST /tasks/{tid}/advance`在一次SQLite事务内核对Brief、成果及最新讨论版本，定稿、验收、记录G0–G2决定，并为可执行下一角色保存调用意图与一轮费用预留；提交后调度。相同请求ID不重发；余额、依赖或版本检查失败整体回滚。运行中、输入变化、旧消息、合并或替代任务不能确认。最终后期成果不能走文字确认捷径，仍需真实视频与五项人工验收。

`studio/handoff.py`沿任务依赖读取全部已验收祖先，而非只读取直接父任务。每项包含准确成果版本、正文、摘要、不确定项、确认时可见讨论与候选记录；全部祖先版本写入下游input_refs，修改总控成果会使更深下游失效。Brief、预算、已有参考、实验、Bible与阶段决定同时作为模型输入。已确认正文优先于历史讨论中的早期建议，候选记录不等于实际入库或验证。无现有假设时，仅将页面展示的候选假设规范化为untested，其他Bible/实验候选不自动导入。

总控负责创作决策收敛，工作台负责落实流程。人类勾选由总控承接受众说明后，仅合并尚未执行的观众节点，writer依赖改指总控；原节点记为merged并保留merged_into，不创建虚假观众成果。取消勾选保留独立观众策略路径。此选择不会启用Gemini，也不证明真实观众或成本。当前短片约定保留完整60秒设计、先实测两个最贵镜头再批量生成，随讨论和方案传递；媒体适配器已接入，真实成本卡点仍需实际生成和账单，不能由文字确认代替。

## 媒体供应商适配（2026-10-03）

`studio/providers.py` 提供独立配置、能力目录、费用估算、持久任务、生成与查询、素材入库、人工核账。官方请求分别使用火山方舟北京与阿里云百炼北京地址；Seedance 支持明确配置的公网 HTTPS 方舟兼容中转站及固定官方地址的 OpenRouter。模型、能力和协议边界见 `docs/media-api.md`。价格来自官方文档的当前快照，普通中转站按用户报价；OpenRouter按模型SKU以美元计费，用户元/秒只作预算参考，不冒充账单。

SQLite `media_jobs` 在外部调用前记录调用意图、输入版本、Brief 版本、配置快照、预留金额和幂等请求。配置快照不含 Key；确认时核对估算所用配置和版本。两项媒体并发队列与文本队列独立，预算统一计算。持久远端任务 ID 后轮询，下载后验证解码并创建素材记录；成功生成不自动通过人类验收，参考变更会保留原版本并标记成果失效。

重启、超时、供应商错误均保留中断任务及未知费用，不自动重发生成 POST。用户取回原结果仅执行查询或下载，模型/目标地址改变则拒绝恢复；缺少可恢复 ID 或 URL 时只能先核账。素材下载使用不带供应商凭证的独立客户端。凭证仅本机保存，公开响应和错误不回显；这仍是单用户本机应用，未实现系统凭证库。

文本角色收到真实供应商能力目录，可规划参考图、seed、负面提示词及成本；分镜讨论通过下述受控动作调用生图/视频，其他角色通过手动入口。原生Harness工具仍关闭，Gemini观众视频分析保持禁用，媒体生成不增加观看或转化验证能力。

## 分镜讨论执行媒体动作（2026-10-04）

`StoryboardReply`扩展讨论交付合同，含最多两个 `media_actions`；原`RoleResult`及六字段提示词哈希保持稳定，既有已确认成果可继续使用。运行时补充明确分镜的授权例外，工具合同/预留额度/真实历史进入上下文。Harness仍走官方SDK文本会话，`media_actions`由工作台宿主解析和执行，不开放shell或把供应商凭证暴露给角色。

`studio/storyboard_tools.py`持久化动作，校验角色、轮次授权、当前运行状态、Brief和输入版本。生成动作调用`providers.generate_media`共用服务，在同一预算事务检查本轮累计及项目费用并存储来源关联。异步生成完成后创建真实素材；聊天查询按来源将状态及预览绑定到对应回复，下一轮得到准确素材信息。额度未用不预留，定稿和自动交接开场不生成。

模型请求与真实结果分开记录，素材生成不等于观看、试听、采用或阶段放行。重启中断未执行意图，不自动重发；原任务查询/下载沿用既有恢复机制。授权不扩展到其他角色、配置编辑、核账或审批。

## 编剧场景表格（2026-10-03）

编剧单次运行及对话均附加presentation_rules，明确场景清单分成剧情、声音/风险/资产、叙事作用三张标准Markdown表格。展示要求不改变既有六字段任务哈希、故事决定或工作流授权。`frontend/src/writerSceneTables.ts`只识别场景清单章节中的既有S编号粗体标题及字段，按场景组织表格；原数据库消息及验收/交接正文保持原样。已是表格、代码块或缺少关键字段的内容不转换，避免丢掉陌生格式。Markdown渲染保持跳过原始HTML，表格容器可聚焦并横向滚动。
